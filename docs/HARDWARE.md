# 하드웨어 — 카메라 선정과 배치

대상: x86 PC/노트북 + USB 카메라 4대, 책상 테스트부터 시작, 총 예산 20만원 내외.

---

## 1. 스펙부터 — 무엇이 왜 필요한가

모델명보다 스펙이 먼저다. 아래 5가지 중 하나라도 어긋나면 AVM 이 제대로 안 나온다.

| 스펙                | 요구값               | 왜 필요한가                                                                                                                                                |
| ------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **화각(대각 FOV)**  | **150° 이상** (권장 170~180°) | 4대로 360°를 덮으려면 각자 90° 넘게 담당하고 코너에서 겹쳐야 한다. 일반 웹캠(60~78°)은 아무리 잘 배치해도 대각선 사각지대가 남는다.       |
| **초점**            | **고정초점(fixed focus) 필수** | 오토포커스가 돌면 초점거리 $f$ 가 변한다. 캘리브레이션으로 구한 $K$ 가 그 순간 무효가 되고 BEV 전체가 어긋난다. **가장 놓치기 쉬운 함정.** |
| **압축 포맷**       | **MJPEG 지원 필수**  | 무압축 YUYV 는 720p30 한 대가 약 440 Mbps. USB 2.0(실효 ~280 Mbps)이면 한 대도 못 돌린다. 아래 2절 계산 참고.                                    |
| **노출/WB 제어**    | UVC 수동 제어 가능   | 오토 노출·화이트밸런스가 카메라마다 따로 놀면 이음선에서 밝기가 계단처럼 튄다. 수동 고정이 답이다.                                              |
| **인터페이스**      | UVC 표준             | 드라이버 설치 없이 OpenCV `VideoCapture` 로 바로 잡힌다. 전용 SDK 요구 제품은 피한다.                                                            |

해상도는 우선순위가 낮다. **720p 로도 충분**하고, 오히려 대역폭이 여유로워 4대 동시 구동이 쉽다.
1080p 는 캘리브레이션 정밀도가 조금 올라가지만 BEV 출력이 2mm/px 수준이면 체감 차이가 크지 않다.

## 2. USB 대역폭 계산 — 4대가 안 돌아가는 진짜 이유

| 포맷 | 1280×720 @30fps 한 대 | 4대 합계 | USB 2.0 (실효 ~280Mbps) | USB 3.0 (실효 ~3Gbps) |
| ---- | ---------------------- | -------- | ----------------------- | --------------------- |
| YUYV (무압축) | ~442 Mbps | ~1.77 Gbps | 1대도 불가 | 4대 빠듯 |
| **MJPEG (압축)** | **~35 Mbps** | **~140 Mbps** | 가능 | 여유 |

즉 **MJPEG 만 강제하면 USB 2.0 포트로도 4대가 돌아간다.** 이 패키지의 `capture.py` 는
`CAP_PROP_FOURCC` 를 MJPG 로 먼저 설정한 뒤 해상도를 잡는다(순서가 중요하다).

`scripts/00_probe_cameras.py --test 0 2 4 6` 으로 실제 달성 FPS 를 먼저 재보고 넘어갈 것.
FPS 가 목표의 절반 이하라면:

```bash
lsusb -t          # 4대가 같은 Bus 아래 몰려 있으면 대역폭을 나눠 쓴다
```

- 노트북이라면 좌/우 측면 포트가 서로 다른 컨트롤러인 경우가 많으니 분산해서 꽂는다
- 그래도 안 되면 640×480 으로 낮춘다 (책상 테스트에는 충분하다)

## 3. 추천 구성 (총 20만원 내외)

가격·재고는 수시로 바뀌므로 **모델명은 예시**로 보고, 위 1절 스펙표로 검증해서 사는 것이 안전하다.

### 카메라 — 1순위: ELP 어안 USB 모듈 × 4

이 바닥에서 사실상 표준처럼 쓰이는 시리즈다. UVC 표준, MJPEG 지원, M12 고정초점 렌즈.

| 항목 | 내용 |
| ---- | ---- |
| 예시 모델 | `ELP-USBFHD01M-L180` (1080p, 180° 어안) 또는 `ELP-USB100W05MT-DL170` (720p, 170°) |
| 센서 | OV2710 (1080p) / OV9712 (720p) |
| 가격대 | 대당 3.5만~5.5만원 (AliExpress 직구 기준) |
| 구매처 | AliExpress ELP 공식스토어, Amazon, 국내 재판매 |
| 장점 | 화각·고정초점·MJPEG 조건을 모두 만족, 자료가 많음 |
| 주의 | M12 렌즈는 손으로 돌려 초점을 맞추는 방식 → **맞춘 뒤 반드시 고정** (4절 참고) |

**720p 170° 모델을 권한다.** 대역폭이 절반이라 4대 동시 구동이 훨씬 안정적이고, 가격도 싸서
20만원 예산에 삼각대까지 들어간다.

### 카메라 — 2순위: 제네릭 OV2710 + 180° M12 렌즈 모듈

AliExpress 에서 "USB fisheye camera module 180 degree OV2710" 로 검색하면 나오는 노브랜드 모듈.
대당 2.5만~4만원. 스펙만 맞으면 동작에는 문제없지만, 개체 편차와 문서 부재를 감수해야 한다.

### 피해야 할 것

| 제품군 | 이유 |
| ------ | ---- |
| 로지텍 C270 / C310 | 화각 60~78°. 너무 좁아 4대로 360°가 안 된다. |
| 로지텍 C920 / C922 | 화각도 좁고(78°) **오토포커스**라 $K$ 가 계속 변한다. |
| "AI 웹캠", 오토 프레이밍 카메라 | 소프트웨어가 화각을 임의로 크롭·변형해서 캘리브레이션이 불가능하다. |
| 전용 SDK 만 지원하는 산업용 카메라 | 이 예산대에선 UVC 표준이 훨씬 편하다. |

### 부자재 (별도 3~5만원)

| 품목 | 수량 | 용도 |
| ---- | ---- | ---- |
| 미니 삼각대 / 클램프 거치대 | 4개 | 카메라를 상자 네 변에 고정. 흔들리면 곧바로 오차. |
| USB 연장 케이블 (2~3m) | 4개 | 5m 넘기면 액티브 리피터 케이블 필요 |
| A4 인화지 / 폼보드 | 약간 | 체커보드·ArUco 마커를 **평평하게** 붙일 판 |
| 줄자 또는 버니어캘리퍼스 | 1개 | 인쇄된 마커 실제 크기 검증용 (필수) |

## 4. 조립 시 반드시 지킬 것

### 초점을 고정한다

M12 렌즈는 나사식이라 돌리면 초점이 변한다. 캘리브레이션 **전에** 다음을 끝내야 한다.

1. 실제 사용할 거리(책상이면 30~60cm)에 있는 물체로 초점을 맞춘다
2. 렌즈 고정 나사를 조이거나, 렌즈-경통 접합부에 소량의 락타이트/순간접착제를 찍어 굳힌다
3. 이후 렌즈를 절대 건드리지 않는다 — 건드렸다면 내부 파라미터 캘리브레이션을 다시 한다

### 오토 기능을 끈다

Linux 에서 `v4l2-ctl` 로 확인·고정할 수 있다.

```bash
sudo apt install v4l-utils
v4l2-ctl -d /dev/video0 --list-ctrls          # 지원 컨트롤 확인

v4l2-ctl -d /dev/video0 -c focus_automatic_continuous=0
v4l2-ctl -d /dev/video0 -c auto_exposure=1     # 1=manual, 3=aperture priority(auto)
v4l2-ctl -d /dev/video0 -c exposure_time_absolute=250
v4l2-ctl -d /dev/video0 -c white_balance_automatic=0
v4l2-ctl -d /dev/video0 -c white_balance_temperature=4600
```

컨트롤 이름은 커널 버전에 따라 다르다(`exposure_auto` vs `auto_exposure`). `--list-ctrls` 로 확인할 것.
`avm360.capture.CameraSpec` 의 `exposure`, `gain`, `wb_temperature` 로도 같은 설정을 줄 수 있다.

**노출은 4대 모두 같은 값으로 맞춘다.** 그래야 이음선 밝기 차이가 처음부터 작다.
그래도 남는 차이는 `photometric.py` 가 겹침 영역 기준으로 보정한다.

### 장치 번호를 고정한다 (Linux)

재부팅하면 `/dev/video0` 이 다른 카메라가 될 수 있다. udev 규칙으로 고정하는 것이 안전하다.

```bash
udevadm info -a -n /dev/video0 | grep -E 'serial|idVendor|idProduct'
```

```
# /etc/udev/rules.d/99-avm-cameras.rules
SUBSYSTEM=="video4linux", ATTRS{serial}=="ABC123", SYMLINK+="cam_front"
```

같은 모델 4대는 시리얼이 없거나 같을 수 있다. 그럴 땐 USB 포트 경로(`KERNELS=="1-3:1.0"`)로
고정하고, **어느 포트에 어느 방향 카메라를 꽂았는지 물리적으로 라벨을 붙여둔다.**

## 5. 책상 테스트 배치 (기본 설정값)

`configs/rig_desk.yaml` 은 아래 배치를 가정한다. 30×20cm 상자를 "차량"으로 삼는다.

```
                    전방 (+X)
                       ▲
          ┌────────────┼────────────┐
          │        [front]          │
          │                         │
   [left] │      ■ 상자 30×20 ■     │ [right]     ◀ 좌측 (+Y)
          │                         │
          │        [rear]           │
          └─────────────────────────┘
```

| 카메라 | 위치 (x, y, z) | yaw | pitch |
| ------ | -------------- | --- | ----- |
| front  | (+0.15, 0, 0.22) m | 0° | 40° (아래로) |
| left   | (0, +0.10, 0.22) m | +90° | 40° |
| rear   | (−0.15, 0, 0.22) m | 180° | 40° |
| right  | (0, −0.10, 0.22) m | −90° | 40° |

- **높이 22cm, 틸트 40°** 는 150° 화각 기준으로 커버리지 95%, 사각지대 1.4% 가 나오는 조합이다
  (`scripts/04_build_lut.py` 로 확인 가능)
- 카메라를 더 낮추면 근거리 사각지대가 커지고, 틸트를 너무 키우면 먼 쪽이 안 보인다
- 이 값들은 **설계 목표치일 뿐**이다. 실제 R, t 는 `scripts/03_calib_extrinsic.py` 로 측정한다.
  자로 재서 넣는 것보다 마커 캘리브레이션이 훨씬 정확하다.

바닥은 **평평하고 무늬가 있는 면**이 좋다. 유리처럼 반사가 심하면 마커 검출이 어렵고,
완전 단색이면 이음선이 맞았는지 눈으로 확인하기 어렵다. 체크무늬 매트나 신문지도 괜찮다.

## 6. 다음 단계로 확장할 때

책상 테스트가 되면 그대로 실차/로봇으로 옮길 수 있다. 바뀌는 것은 설정값뿐이다.

- `configs/rig_desk.yaml` 의 `bev` 범위를 넓히고(예: ±5m), `vehicle` 치수를 실제 값으로
- 카메라 `mount` 위치를 실제 장착 위치로 (그리고 다시 외부 파라미터 캘리브레이션)
- 마커를 크게 인쇄해서 더 멀리 배치 (`07_make_markers.py --size 0.20`)

USB 4대로 실차까지 가는 것은 케이블 길이(5m 넘으면 신호 문제)와 동기화 때문에 한계가 있다.
그 단계에서는 GMSL2 카메라 + 디시리얼라이저 보드 + Jetson 조합으로 넘어가는 것이 정석이다.
