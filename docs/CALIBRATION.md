# 캘리브레이션 절차

AVM 품질은 거의 전적으로 캘리브레이션 정확도로 결정된다. BEV.md 6-(B)절에서 정리했듯,
인접 카메라 이음선이 어긋나 보인다면 원인은 대부분 $R, t$ 오차다.

순서는 **내부($K, D$) → 외부($R, t$)** 다. 외부 파라미터를 풀 때 내부 파라미터를 쓰기 때문에
순서를 바꿀 수 없다.

---

## 0. 준비

```bash
cd study/avm360
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/00_probe_cameras.py                 # 장치 확인
.venv/bin/python scripts/00_probe_cameras.py --test 0 2 4 6  # 4대 동시 구동 확인
```

여기서 MJPG 로 안 잡히거나 FPS 가 목표의 절반 이하면, 캘리브레이션으로 넘어가기 전에
`docs/HARDWARE.md` 2절로 먼저 해결한다.

**렌즈 초점을 고정했는지 다시 확인한다.** 캘리브레이션 후에 초점을 건드리면 전부 무효다.

## 1. 내부 파라미터 — $K$, $D$

### 체커보드 준비

- 9×6 **내부 코너**(= 10×7 칸) 패턴을 인쇄한다. 칸 수가 아니라 코너 수 기준이다.
- **딱딱한 판에 평평하게** 붙인다. 종이가 휘면 그 휨이 그대로 왜곡계수에 섞여 들어간다.
- 인쇄 후 자로 한 칸의 변을 재서 `--square` 에 미터 단위로 넣는다 (예: 25mm → `0.025`).

> BEV.md 에서 정리했듯 칸의 **절대 크기는 $K$ 자체에는 영향이 없다**(칸이 정사각형이라는
> 사실만 중요하다). 다만 여기 넣은 값이 이후 $t$ 의 단위를 결정하므로, 실측값을 넣어두면
> 전체 파이프라인이 미터 단위로 자연스럽게 통일된다.

### 촬영

카메라 **한 대씩** 진행한다.

```bash
.venv/bin/python scripts/01_capture.py --mode intrinsic --device 0 --name front
```

- `a` 키로 자동 촬영을 켜면 보드가 검출될 때만 일정 간격으로 저장된다
- **20~30장**, 다음 조건을 고루 채운다:
  - 보드가 화면 **중앙뿐 아니라 네 귀퉁이**에도 오도록 (어안은 가장자리 왜곡이 심해서,
    가장자리 샘플이 없으면 $D$ 가 제대로 안 나온다)
  - 정면뿐 아니라 **좌우·상하로 기울인** 자세 (기울기가 없으면 $f_x, f_y$ 가 잘 안 갈린다)
  - 화면을 꽉 채운 근접 샷과 작게 나온 원거리 샷을 섞는다
- 흐릿한 이미지는 저장하지 않는다. 모션 블러는 코너 검출 정밀도를 크게 떨어뜨린다

네 대 모두 찍었으면:

```bash
.venv/bin/python scripts/02_calib_intrinsic.py --all --square 0.025
```

### 결과 확인

```
[front] 27장 사용, RMS = 0.412px
        fx=486.2 fy=486.9  cx=641.3 cy=358.7  D=[-0.031, 0.004, -0.002, 0.0]
```

| 점검 항목 | 정상 범위 | 벗어나면 |
| --------- | --------- | -------- |
| RMS 재투영오차 | **1.0px 미만** (0.3~0.6px 이면 좋음) | 흐린 이미지를 빼고 재시도. 보드가 휘었는지 확인 |
| $f_x$ vs $f_y$ | 서로 5% 이내 | 픽셀이 정사각형이 아니거나 보드 기울기 샘플 부족 |
| $c_x, c_y$ | 이미지 중심의 15% 이내 | 보드가 화면 한쪽에만 몰렸다. 고루 재촬영 |

## 2. 마커 배치 — 지면 기준점 만들기

AVM 은 카메라 4대가 서로 다른 방향을 보므로 체커보드 한 장을 넷이 동시에 보기 어렵다.
대신 지면에 마커를 **차량 좌표계 기준 알려진 위치**로 깔아두고, 각 카메라가 자기에게 보이는
마커만으로 $R, t$ 를 푼다. 모든 마커가 같은 좌표계로 정의되어 있으므로 결과 $R, t$ 도
자동으로 같은 기준을 갖는다 — 이것이 BEV.md 6-(B)절 "정렬은 캘리브레이션 단계에서 이미
끝나 있다"는 말의 실체다.

```bash
.venv/bin/python scripts/07_make_markers.py --size 0.06
```

`out/markers/sheet.png` 를 **100% 배율(맞춤/축소 없이)** 로 인쇄한다.

> **인쇄 후 반드시 자로 검증한다.** 프린터 기본 설정이 "여백에 맞춤"이면 몇 %씩 줄어들고,
> 그 오차가 그대로 $t$ 의 스케일 오차가 된다. 마커 검은 사각형 한 변이 정확히 60mm 인지 잰다.
> 다르면 실측값을 `configs/markers.yaml` 의 `marker_size` 에 넣는다.

배치:

- 원점은 차량(상자) 중심, **+X 가 전방, +Y 가 좌측**
- `07_make_markers.py` 가 출력한 좌표대로 바닥에 붙인다
- 마커 이미지의 **위쪽이 전방(+X)** 을 향하게 놓는다
- 평평하게 붙인다. 들뜨거나 구겨지면 그만큼 오차다
- 각 카메라가 **최소 2개**(권장 3~4개)를 보도록 배치한다

## 3. 외부 파라미터 — $R$, $t$

4대 **동시**로 촬영한다. 이때 카메라를 움직이면 안 된다.

```bash
.venv/bin/python scripts/01_capture.py --mode extrinsic --devices 0 2 4 6
```

화면에 카메라별 마커 검출 수가 뜬다. **네 대 모두 2개 이상**이 되면 `SPACE` 로 저장한다.

```bash
.venv/bin/python scripts/03_calib_extrinsic.py
```

### 결과 확인

```
 front  위치(x,y,z)=(+0.149, -0.001, +0.221)m  roll=-0.1° pitch=+40.1° yaw=-0.0°
         마커 4개(id [0, 1, 4, 6]), 재투영 RMS = 1.22px
```

| 점검 항목 | 정상 | 벗어나면 |
| --------- | ---- | -------- |
| 재투영 RMS | **3px 미만** | 마커가 들떴거나, $K$ 가 부정확하거나, 마커 크기값이 틀렸다 |
| 위치 (x,y,z) | 줄자로 잰 값과 **1~2cm 이내** | 마커 배치 좌표를 잘못 입력했을 가능성이 높다 |
| yaw | 설계값과 몇 도 이내 | 카메라 방향을 잘못 매칭했는지(front↔rear 등) 확인 |

위치가 자로 잰 값과 크게 다르면 **부호나 축을 헷갈린 경우**가 대부분이다.
+X 전방, +Y 좌측, +Z 상향임을 다시 확인한다.

## 4. LUT 생성 및 검증

```bash
.venv/bin/python scripts/04_build_lut.py
```

```
  전체 커버리지 :  95.0%
  사각지대      :   1.4%
```

- **사각지대 5% 초과**면 배치를 조정한다: 카메라를 더 높이거나, 틸트를 키우거나,
  화각이 더 넓은 렌즈를 쓰거나, BEV 범위를 줄인다
- `out/coverage.png` 로 어느 카메라가 어디를 담당하는지 색으로 확인할 수 있다

```bash
.venv/bin/python scripts/05_run_avm.py --devices 0 2 4 6
```

`s` 키로 이음선을 표시해서, 이음선을 가로지르는 직선(바닥 타일 경계, 테이프 선)이
**꺾이지 않고 이어지는지** 본다. 이게 최종 품질 지표다.

## 5. 문제 해결

| 증상 | 원인 | 대처 |
| ---- | ---- | ---- |
| 이음선에서 직선이 꺾인다 | $R, t$ 오차 | 외부 파라미터 재캘리브레이션. 마커를 더 많이/더 넓게 배치 |
| BEV 전체가 한쪽으로 밀림 | 마커 배치 좌표 입력 오류 | `configs/markers.yaml` 의 x, y 부호 확인 |
| 중심에서 멀수록 어긋남이 커진다 | $D$(왜곡계수) 부정확 | 내부 파라미터 재캘리브레이션, **화면 가장자리 샘플** 추가 |
| 스케일이 안 맞음 (전체가 크거나 작음) | 마커/체커보드 실측 크기 오류 | 인쇄물을 자로 재서 값 수정 |
| 이음선에서 밝기가 계단처럼 튄다 | 오토 노출/WB 작동 중 | `v4l2-ctl` 로 수동 고정 (HARDWARE.md 4절) |
| 시간이 지나며 점점 어긋난다 | 오토포커스 작동 또는 거치대 흔들림 | 초점 고정, 거치대 단단히 고정 |
| 세워진 물체가 길게 늘어난다 | **정상** | IPM 의 평면 가정 위반. BEV.md 2절 참고 |

마지막 항목은 버그가 아니라 IPM 의 원리적 한계다. 지면에서 떨어진 점은 높이 정보가 없어
$Z=0$ 평면에 억지로 투영되므로, 카메라에서 멀어지는 방향으로 늘어난다. 시뮬레이션에서
`scripts/06_simulate.py` 로 이 현상을 눈으로 확인할 수 있다.

## 6. 하드웨어 없이 미리 연습하기

카메라가 오기 전에도 전체 절차를 그대로 돌려볼 수 있다.

```bash
.venv/bin/python scripts/08_selftest.py    # 렌더링 → 캘리브레이션 → 검증 왕복
.venv/bin/python scripts/06_simulate.py    # 결과 이미지 눈으로 확인
```

`08_selftest.py` 는 설계값으로 가상 이미지를 만든 뒤 **그 이미지만 보고** $R, t$ 를 다시
추정해서 원래 값과 비교한다. 통과하면 캘리브레이션 → LUT → 블렌딩 전 과정이 정상이라는 뜻이다.
